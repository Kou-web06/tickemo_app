# Tickemo（Swift / Native版）

Tickemo iOSアプリの Swift（SwiftUI）ネイティブ実装。旧 React Native 版からの完全移行版で、本リポジトリは Swift 専用（移行元の RN 実装は別リポジトリで管理）。

## アプリ概要

### 公開URL
- [デベロッパWebサイト](https://www.tickemo.com/)

### 主な機能

- **Collection（コレクション）** - ライブ情報を美しいチケット形式で管理
  - アーティスト名、ライブ名、日時、会場、QRコード、メモなどを保存
  - 次回のライブをカウントダウン表示
  - 複数チケットの一覧表示と詳細ビュー

- **Calendar（カレンダー）** - 次のライブまでの日数をリアルタイム表示
  - 登録したライブを日付ごとにカレンダー上で一覧表示
  - 日付タップで当日のライブ情報をすぐに確認できる

- **Report（レポート）** - 推し活の統計情報を可視化
  - 観戦ライブ数やトップアーティストなどの累計データを表示

- **iCloud同期** - Core Data + CloudKit によるデバイス間の自動同期
  - チケット・セットリストの記録をすべてのデバイス間でシームレスに共有

## 制作背景

### 課題・ニーズ

推し活をしているユーザーの多くは、複数のライブチケットを紙やスマートフォンのスクリーンショットで分散管理しており、以下の課題を抱えていた。

1. **ライブ情報の管理** - チケットがメールや写真フォルダ、スクリーンショットなどに分散している
2. **次のライブの把握のしやすさ** - 登録したチケットから「次いつ行けるのか」が一瞬でわかる仕組みがない
3. **思い出の可視化** - どのアーティストのライブに何度行ったのか、簡単には思い出すことができない
4. **美的価値の欠落** - 既存のチケット管理アプリは機能重視で、推し活の「楽しさ」を表現しきれていない

### 目的
「ライブの思い出を、綺麗に、分かりやすく管理する体験」を提供することで、推し活をより楽しく、充実させること。

## 技術選定

React Native版からのフルリライトにあたり、パフォーマンス・OS標準機能との親和性・長期的な保守性を優先してネイティブ実装に切り替えた。

### 言語・フレームワーク・プラットフォーム

| 技術 | 意図 |
|------|------|
| **Swift / SwiftUI** | 宣言的UIによりレイアウト・アニメーションの実装コストを抑えつつ、iOSネイティブのパフォーマンスと表現力を最大限に活かすため。 |
| **Core Data + NSPersistentCloudKitContainer** | ローカルDBとiCloud同期（デバイス間の自動同期）を1つの仕組みで実現するため。独自の同期API実装を避け、Appleの標準機構に乗ることで信頼性を確保。 |
| **MusicKit** | Apple Musicのカタログ検索・再生を統合し、セットリストの曲・アーティスト情報を正確に取得するため。 |
| **MapKit** | ライブ会場の住所検索・地図表示をOS標準機能で完結させるため。 |

### UI・アニメーション

| 技術 | 意図 |
|------|------|
| **Lottie (lottie-ios)** | RN版で使用していたLottieアニメーション素材をそのまま流用し、同じモーションデザインを再現するため。 |
| **SwiftUI Shape / Canvas / ImageRenderer** | チケット・CD・レシートのシェアカードなど、固定レイアウトの複雑な図形をコードベースで再現し、画像として書き出すため（RN版の React Native SVG に相当）。 |

### 状態管理・データベース・課金

| 技術 | 意図 |
|------|------|
| **Core Data** | デバイスローカルへの永続化を、iCloud同期の仕組みと一体化した形で扱うため（RN版の AsyncStorage / SQLite に代わる仕組み）。 |
| **@Observable / SwiftUI Environment** | Redux・Zustand相当の役割を、Appleの標準的な状態管理機構でシンプルに実現するため。 |
| **RevenueCat** | Plusプラン（課金プラン）の管理をRN版から引き続き簡略化するため。RN版と同一SDKを採用し、移行後も同じ課金基盤を継続利用。 |
